## Safety behavior

- exhaustive mode without --limit refuses to run unless --allow-full-exhaustive is explicitly specified.
- --start is 1-based and may be combined with --limit for deterministic batches.
- cross/exhaustive cases use deterministic IDs so both peers can synchronize using the same start/limit range.
- generated PFS ESP proposals use separate CREATE_CHILD_SA and expected CHILD KE verification.
- no global XFRM flush was added.

## Runtime limitation

The container used to build v12 does not contain the user's real strongSwan 5.9.13 / 5.8.4 two-PC environment. Therefore the new cross/exhaustive/custom generated modes require final runtime validation on PC-A/PC-B. The baseline data path itself is inherited from the real-PC validated v11 implementation.
